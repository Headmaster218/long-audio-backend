# dev29：自动任务准入前的所有者忙等待

版本：`0.2.0rc3.dev29`。本版仅对自动文本任务中尚未派发的所有者读取忙状态增加原地等待，并保存有限的子阶段诊断。模型、存储格式、任务身份、资源配额和默认关闭策略不变。

## 等待边界

`validate_dispatch` 在提交时直接返回 `busy`，且固定原因是 `owner_lock_busy` 或 `one_total_handoff_slot`，才产生进程内的未派发凭据。此时没有读操作被所有者接纳。已经接纳但未完成的操作、已完成的失败、普通公开 `cell_owner_unavailable` 字符串以及其他读取类别，都不能产生该凭据。

自动文本驱动在原有的内层 `before_spawn` 和 `before_admission` 检查处，遇到该凭据后可取消地等待，每次最多 100 ms。之后重新执行完整的同一来源、租约、取消和准入检查。已经构造的驱动、已接受任务、来源副本、租约、permit、原始任务及驱动截止时间保持不变；已有的等待子进程不重新创建。每次验证保持自己的既有有界读取预算，外层等待不重置任务或驱动时钟。

子进程在 stdin 准入字节前等待。发送该字节前仍检查等待子进程存活、资源、控制器取消、任务取消、租约取消和两个原始截止时间；最终资源采样期间发生的取消或到期也会拒绝。等待不持有所有者操作、数据库事务或 permit 条件锁。持续忙状态可到期失败；没有把未知操作或历史尝试重新运行的许可。手动任务、说话人 probe 和 `before_input` 保持原有策略。

## 持久诊断与兼容性

既有不超过 1,024 字节的终态 outcome 增加固定的启动子阶段及所有者读取状态、原因和是否已接纳标志。它不包含消息、路径、SQL、参数、音频或 stdout。若忙等待后因取消、资源或截止时间失败，外层 failure 表示终止原因，附带的 owner_read 只表示最后观察到的忙读取，不能解释为另一次已接纳操作的失败。

`invocation_possible` 和调用计数依据继续采用原有保守语义；进入 start 不等于证实 native 已执行。没有新增表、账本、旧行改写或历史重放。以前两个 start 阶段失败的具体下层原因及 native 计数仍未知。

## 模型无关验证

- 37 个专项测试通过：真实本地所有者争用、SQLite 来源与标准库 stdin 等待子进程；验证同一子进程只获一次准入、正向等待和清理，以及取消、撤销、资源、到期、已派发操作和手动/probe 的拒绝边界。声学证明与模型返回使用模拟接口。
- 受影响分组分别为 114 个测试及 23 个子测试通过、修正后的完整 API 文件 32 个及 6 个子测试通过、无结果终态文件 58 个通过。分组存在重叠，不能相加为独立完整测试总量。
- 首次专项的 35 通过 / 2 失败保留：测试在正确退休后读取已清空控制器。保存返回状态后，完整专项通过。
- 原始第二回归组的 62 通过、21 个子测试通过及 4 个失败子测试仍是失败记录：两个旧测试工厂缺少应用早已传入的 speaker_links 参数。仅修正工厂签名，保持关闭次序与未解决所有权断言，完整 API 文件随后通过。

以上不是模型质量或长时运行验收。标准离线构建、全新安装与安装目标测试另行记录。
