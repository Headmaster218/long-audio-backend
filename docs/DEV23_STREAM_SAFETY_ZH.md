# dev23：流式边界与队列竞争修正

开发版本 `0.2.0rc3.dev23`，基础版本为 dev22。源码与测试公开，不分发音频、转写、向量、模型权重或本地运行配置。没有创建正式 release/tag。

## 功能与安全边界

1. 重启 seam：左侧历史 compact 不变；右侧 fresh capture run 对精确保留的左右 PCM 发起新 native 查询。只使用这次新响应的标签，不沿用旧 run 的局部身份。来源、范围、runtime、重放覆盖和权威验证仍严格。缺少足够重放时明确拒绝。
2. 安全切点：原始 native 边界通过严格帧验证后，间隙、中点、保护距离和下一 origin 在整数采样坐标中传播。合法半帧内部中点选择较早采样点；外部真实非整帧坐标仍拒绝，不引入通用四舍五入容差。
3. 结果存储诊断：仅记录固定操作阶段、异常类别、SQLite code/name、数值 errno、VM 步数和首先观测到的 deadline/VM 预算原因，不记录 SQL、异常原文、路径或音频内容。250 ms / 50,000 VM 步等既有上限不变；写入或不确定提交不自动重试。
4. 主队列竞争：仅自动模式下，`BEGIN IMMEDIATE` 尚未取得事务且数值错误码属于 BUSY/LOCKED 时，Worker 释放 claim probe 并用 stop-event 等待 100 ms 后重新检查主任务。队列和游标不变，不将“无法检查”视为空闲，也不在该分支调度 MOSS。事务已开始、提交确认不明、非 BUSY 错误和普通模式保持原失败行为。

不新增数据库表或模型依赖；默认关闭的可选开关仍保持默认。可选 store 使用 `native-owned-cell-store-policy-restart-replay-v1`：旧 policy 明确拒绝，不自动迁移或删除数据。升级前停服并完整备份。选择全新可选状态时保留旧 store 与配对主数据库；旧历史兼容性和降级尚未合资格。

## 安装与运行

沿用 `requirements-runtime-dev9.lock.txt` 和 `requirements-build-dev9.lock.txt`。可使用标准 `python -m pip wheel --no-deps --no-build-isolation .` 构建，再将 wheel 安装到独立环境。离线时使用 `--no-index` 与已准备好的固定依赖。原有模型/runtime 许可证及第三方 notices 必须保留。通过 `python -m audio_backend --help` 查看现有开关；此版本没有新增自动下载、网络服务或阈值参数。

本快照已完成标准离线 wheel 构建、全新 target 安装及 127 个包文件的源码/wheel/target 逐字节核对，依赖与第三方许可证保持一致。默认关闭的应用构造/import、7 项 CLI 帮助/前置检查通过；随后对安装后的产品通过 81 个模型无关测试，并确认导入来自安装 target。既有合资格依赖被复用，没有重新下载依赖、启动真实服务或运行模型。

首轮安装验证在 26 个测试通过后因一个新 frame-cut 测试缺少 `RESET_REPLAY_REPORT_DIR` 而 exit 1；其在失败前的产品断言已通过。原始失败保留，后续仅设置有界报告目录并在全新 fixture 中执行相同的 pytest 选择，81 个通过。未重建或重复安装 wheel。测试运行的 source manifest 保留；最终只更新本段文档，所有包文件、测试和构建配置保持相同。直接运行该 frame-cut 测试文件时应将 `RESET_REPLAY_REPORT_DIR` 指向一个新的、父目录已存在的测试报告目录。

## 分开的回归与实际观察

- 重启候选：28 个专项通过；另有 202 个相关回归通过，2 个长逻辑 fixture 明确未选。假 provider 越界与两个测试断言错误修正前的失败均保留。
- 帧切点：39 个专项通过；相关组 280 个通过、66 个 subtests，通过修正旧 fake fixture 后另有 12 个通过、68 个 subtests。首轮 3 项 fixture 失败保留，不能加总成一次完整套件通过。
- 结果存储诊断：58 个存储/诊断测试通过，另有 59 个历史/API/自动调度测试通过。
- BEGIN 前 claim 退避：36 个测试及 4 个 subtests 通过，另有 108 个自动调度/诊断回归通过。最初 16 项新 fixture setup 错误、20 项通过的失败轮保留，修正仅为读取 create_session 返回字典的 id。

上述回归属于分别冻结的源码候选，存在交叉覆盖，不能相加当作一次运行，也不证明最终安装包或长时模型行为。

固定 42 秒重启案例完成 7 个自动结果和一个精确重启 seam。原 helper 因历史分页容量假设退出 1；独立关闭模型的 GET 补充读取全部 7 个结果通过。局部说话人 probe 的原始失败原因未完整保留；事后相同 proof 中没有达到 2 秒的合资格干净片段，不据此认定重启身份链接成功。

最近 1,800 秒计划输入由中文、AMI、事件、示例语音与显式重复/数字静音组成。实际在 913.578 秒停止：API 接收 820.5 秒，完整发布 789 秒，最后观测主提交 766.96 秒，最高已接收但未提交量 84.32 秒。端到端墙钟/主提交音频比约 1.191，包含 pacing、启动和处理，并非纯模型 RTF。七个已观测任务中两个有验证结果，五个中断且精确调用次数不明；另有 38 个候选等待。原始整体状态为失败。

本轮明确捕获主 Worker 在 BEGIN 前数据库锁竞争时退出；本版退避针对该故障。存储诊断也捕获瞬态 SQLite BUSY_RECOVERY 261 和 BUSY 5，限定只读 GET 重试后有成功响应。更早被屏蔽的 503 原因仍未知。所有已拥有子进程完成正向等待，观察到无存活后代；采样峰值加预留约 3.23 GB，不是连续峰值保证。

## 尚未解决

- 主任务声明会取消已有自动 MOSS，导致重叠任务中断；公平、非抢占调度尚未纳入此快照。
- `primary_ownership_uncertain` 可能在 Worker 退出之前出现，其精确历史原因未保存。保持 fail-closed，不能用后续一次正常采样擅自解除。
- 30 分钟全功能连续测试、12–48 小时实际运行、全语音吞吐、Windows/Vulkan 与真实设备录音仍未通过完整验收。
- 暂定统一转写和录音内标签链接不等于准确率提升、跨天全局人物身份、所有重叠语音均已恢复。

后续实际运行须分别验证上述未完成项；本快照仅保存已审阅且有相应测试的修正，不扩大历史测试结论。
