# dev31：有限采样恢复与自动文本外层启动前等待

版本：`0.2.0rc3.dev31`。本版在既有默认关闭的可选能力上修正两个有限边界，不增加依赖、数据库表、模型重放或后台线程。旧结果、时间戳诊断和来源证明保持原样；无需数据库迁移。所有默认超时、采样和资源上限不变。

## 外层启动前的未派发忙等待

自动文本任务的控制器在外层 `before_spawn` 检查中，仅对既有私有标记确认的即时 `owner_lock_busy` 或 `one_total_handoff_slot` 等待。此标记只来自尚未接纳任何 Operation 的 submit 返回分支，不从公共 `cell_owner_unavailable` 文本推断。

每次等待不超过 100 ms，可取消，受原始驱动和已接纳任务的剩余时间共同限制。复用同一驱动、任务身份和租约，每轮重新检查来源、许可及资源；最后一次资源采样后再次检查控制器、任务和租约取消，以及两个原始截止时间。等待到期仍失败，不生成第二个子进程。

既有已关闭只读 SQLite 竞争标记仍是独立分支。`before_input`、内层启动和准入门控、手动任务与说话人 probe 策略不因这次外层修正改变。已派发但未完成的操作、已完成失败的读取和未知尝试仍不可重放。持久 outcome 中的 `owner_read` 可表示此前最后一次未派发忙观察；后续取消、资源或截止时间失败的外层类别才是终止原因，不能把旧 busy 元组误记为一次新派发失败。

## 采样不可用与当前资源恢复

只有真实资源采样器在既有 250 ms 墙钟或 4,096 枚举行预算处生成的私有认证标记，可以进入 `primary_sampling_unavailable`。相同错误文字、伪造或一般 `AdmissionError` 不具有恢复资格。128 个身份上限、根进程丢失、访问拒绝、PID 复用、已知未记账进程、清理不确定等仍保持 sticky 拒绝。

恢复只尝试一次到期观测，间隔至少一秒。单一在途 token 和代际检查阻止并行调用绕过间隔，也阻止旧成功覆盖新的绑定、退休、失败或关闭。完整身份核对、所有原始句柄和子进程家族核对全部成功后，才一起提交资源视图、记账计数和暂存子进程映射。部分采样不提供准入依据；过期结果、被占用 token 或冷却期间的跳过不新增失败计数或 sticky 错误。

既有 Worker 交接路径在可选任务选择之前提供一次到期恢复机会，因此没有可运行候选或主输入结束时也可恢复。清理完成、句柄映射为空或一次可选准入请求本身不能清除等待。可选模型已经启动后的资源检查失败仍按原策略取消并要求原始句柄正向等待、清理；资源视图恢复不自动授予模型执行许可。

这只建立后一次完整的当前资源记账，不证明历史进程正常退出，也不证明从未存在不可见后代。dev28 的同一采样预算内单次 census 重采样及 dev26 的独立 confirmed-exit 计数继续保持各自语义。

## 有限 health 字段

permit 增加以下 RAM 状态，不运行日志回调，不保存 PID、路径或进程参数：

- `primary_sampling_pending`：当前是否仍需恢复采样。
- `primary_sampling_exhaustions`：已认证预算耗尽次数，饱和于有符号 32 位整数上限。
- `completed_primary_sampling_recoveries`：完整原子提交的恢复次数，同样饱和。
- `primary_sampling_failure`：首次固定记录，含 operation、phase、reason=`process_sample_budget`、budget=`wall` 或 `rows`，以及已有观测得到的 `last_elapsed_ms`、`rows_observed`。毫秒值有限且封顶，不能表示时为 null；不为诊断增加时钟或进程查询。

首次记录在恢复后仍保留。发生后续 sticky 故障或关闭时，不能只看 pending 或计数决定可恢复；既有 `primary_ownership_uncertain` 和 `primary_observation_failure` 仍优先阻塞。对外资源检查的非采样跳过仍返回既有 `AdmissionError('process_sample_unavailable')`，不放行未知资源占用。

## 模型无关验证与历史范围

外层等待专项 26 个用例通过，相关回归另有 110 个及 23 个子测试。覆盖真实 SQLite owner 单槽占用、释放、截止时间、取消和租约事件，真实 stdin 门控的标准库子进程及正向清理，以及未派发与已派发操作的区别；声学证明和 native 回执由受控替身提供。

采样恢复专项 42 个用例通过，覆盖认证预算分支、单一在途观测、代际竞态、原子家族记账、至少一秒间隔、sticky 负例、固定计数和空队列 Worker 交接。该专项的 census、资源数值及原始句柄均为受控替身。相关采样组另通过 124 个及 10 个子测试，其中既有用例包含正向等待的标准库子进程。

Worker 相关组的首次运行因累计临时 SQLite fixture 超过 16 MiB 而被终止，原日志和失败 fixture 保留，未把进度点计为通过。随后只增加标准 pytest 的成功用例临时目录清理选项，源代码、选择和上限不变，新的运行通过 82 个并明确排除两项重型 core-yield 几何参数。该组不提供新的完整几何资格。以上通过进程均正向等待结束；专项 runner 的 RSS 是 pytest 进程抽样值，不是所有后代的聚合峰值。

本版尚无真实模型运行证据。[dev29 长混合输入运行](DEV29_LONG_MIXED_RESULT.md) 仍是退出码 1 的未完成实际结果：历史采样失败的墙钟/行数子型未保留；一个启动前无结果的持久回执另确认零调用。不能把新源代码的模型无关通过回填到旧实际运行，也不能把 schema-clean 或当前资源恢复解释为识别、时间戳或说话人准确率验证。
