# Primary observation/history production slice map

Design-only finite scope proposal. The authority, accounting and verified-retirement contracts are prerequisites; exact DDL, resource admission and integration remain gates. The isolated 2,884-row comparator passed its model-free fixture, not production identity or throughput qualification. No model run or new database benchmark is authorized by this map.

Source baseline: `Headmaster218/long-audio-backend` commit `b13c6fc4f1e5f3d9f86b68a222d4cab3c78101de` (operational baseline `49cd724dda5595aee29eaf1d7da2f41739b43d08`). Comparator evidence is retained under `prototypes/history_comparator/`; it does not qualify production resource use or identity accuracy.

## Finite module boundary

Existing modules under `audio_backend/`:

1. `native_owned_cell_capture.py`: an independently caught optional live-copy hook inside `Capture.prepare`; no optional exception reaches its required-primary failure boundary. Wire through existing `capture.authority.store.moss_automatic.jobs`.
2. `recording_primary_probe.py`: direct-primary clean selection/proof binding using the existing packet/source/current checks; preserve original crop rules. This is a new producer kind, not a fake MOSS query/job.
3. `worker.py`: hold only an opaque provisional-copy handle; publish it only after positive primary commit acknowledgement; unconditional finally-abort handles every later failure/seam/cancel path. Existing `_automatic_handoff` remains the turn boundary.
4. `moss_handy_jobs.py`: separate one-slot primary pending owner from MOSS `_live`; split text readiness, primary-slot readiness and actual executing-child state. Own copied audio, typed reservation, fresh invocation, positive cleanup, durable success/failure and exact unknown-ack closure; also own the single on-demand comparison task and its tracked cancellation/join/backpressure. Integrate stop/session invalidation without losing an existing unknown child.
5. `moss_automatic.py`: pending-primary readiness can request the existing finite automatic turn even with no MOSS candidate. If both classes are ready, alternate a text/probe attempt deterministically; advance the class after the bounded attempt, including refusal, so one failing class cannot starve the other. One selected-class attempt per eligible primary cohort; existing cohort fairness and maintenance ordering remain.
6. `native_execution_permit.py`: add `automatic_primary_probe` to reserve-kind/automatic-turn checks, queued-primary cancellation exemption and running-primary checks. Acquire synchronously inside Worker thread's automatic turn before launching the existing manager thread. Do not weaken thread-local authority or text-only publication guard. Separately add the narrow explicitly accounted comparison CPU/RAM resource token described below; it is not another inference owner kind.
7. `recording_speaker_links.py`: versioned typed producer/proof adapter and reusable existing validation/geometry rules. Legacy version 3 scorer, thresholds and existing scopes remain unchanged; the scalable comparator is a new decision-policy version, not a raised `MAX_NODES` argument.
8. `recording_speaker_link_store.py`: route explicitly new-policy recordings to the additive history path; preserve old scopes/uniqueness; recognize exact old/new known schema forms and install the old-binary-refusal marker. Shared old-plus-new quota checks apply to both writers.
9. `storage.py`: initialize new exact schema/triggers after primary-provenance and required primary fields exist, in the existing schema transaction. No capture-time primary transaction is expanded with optional history writes.
10. `native_owned_cell_store.py`: source-mismatch callsites notify durable semantic invalidation; generic `revoked()`/`close_admission()` retain their separate process-lifetime purpose.
11. `lifecycle.py`: same-transaction new-history erasure and the narrow marker-gated cleanup adapter. Ordinary session erasure still deletes derived evidence. No new automatic retention-age policy is included; routine retirement requires a separately qualified existing caller/policy and all source eligibility/pins.
12. `transcript_contract.py`: whitelist/format exact-ref annotations and explicit current versus pending/historical/invalid status. This formatter alone does not implement paging.
13. `transcript_store.py`: narrow new-policy adapter in `_speaker_annotations` and `_revision`. Its current path (`:475–560`) calls `read_saved_for_recording` once per recording, reserves `MAX_DECISION_BYTES`, materializes the full saved decision and searches lists. Retain that path for legacy scopes. For new history, gather only this transcript page's exact primary refs and real MOSS job/result/phrase keys; read bounded scope headers and indexed matching decision rows through the history helper in the same caller snapshot. Stream all matches for each ref into the existing unanimous-status/identity rule; stopping at a page limit is incomplete, never first-match wins. Share the existing optional byte/query budget and preserve primary text when an overlay is unavailable. `_revision`/`read_session_revision` must bind the new history/authority/current-decision header revisions so stale cursors cannot silently mix snapshots.
14–15. `settings.py` and `__main__.py`: explicit opt-in new policy/configuration route, validated and frozen per recording. Proposed names are `recording_primary_observation_policy` (off or reviewed version ID) and `recording_primary_observation_interval_seconds` (positive integer, required when enabled); no implicit production cadence default is selected here. Exact profile values must be approved before implementation. Add a separate proposed boolean `recording_speaker_history_read_enabled` for passive historical projection; it must not imply producer/model enablement.

Two new modules, both called by existing owners rather than new services:

16. `recording_speaker_history.py`: bounded primary-DB reservation/certificate/proof accounting, source states/retirement, indexed destructive-change triggers and snapshot I/O.
17. `recording_speaker_history_compare.py`: compact exact comparator adapter, resumable append-only score prefix and bounded round/ranking/projection work. The isolated prototype is evidence for this adapter, not a drop-in implementation.

Read/reuse without intended operational edits: `recording_primary_provenance.py` for immutable audit packets; `recording_speaker_probe_runner.py` for fresh process execution (its private `job_id` is opaque correlation); `app.py` already wires automatic.capture/jobs. `recording_overlap.py` cancellation/abort writes and `transcript_revision.py` provide source/lifecycle context; new precise dependency triggers belong to history schema, rather than changing the existing broad transcript-revision meaning. Any newly discovered writer/wiring edit must be added explicitly to the reviewed allowlist.

## Exact additive table responsibilities to review

All proposed names use a new `_v1` suffix and exact schema validation; this is not executed DDL:

- `recording_history_scopes_v1`: immutable recording policy/space, persisted sampling state, history/authority revisions, blocked reason and current/building decision pointers.
- `recording_history_attempts_v1`: idempotent typed attempt, reservation owner/charge, bounded terminal diagnostic; unknown outcomes never authorize inference.
- `recording_history_certificates_v1`: immutable sequence, owning attempt/basis, exact vector BLOB/header/digests and fresh-cleanup binding.
- `recording_history_bases_v1`: immutable shared producer-proof basis, one per successful attempt, shared by at most four MOSS certificates or one standalone primary certificate.
- `recording_history_objects_v1`: immutable typed copied Receipt/MOSS proof objects, exact digest/body/charge and checked edge refcount.
- `recording_history_object_refs_v1`: basis-to-owned-object and exact external primary-packet references; explicit kinds and bounded keys.
- `recording_history_dependencies_v1`: immutable indexed source/mapping/primary-ref keys and current-fact digests, never disposable comparison hints.
- `recording_history_sources_v1`: source-version state, source-specific admission revision/count and committed required-end fence.
- `recording_history_retirements_v1`: immutable bounded retirement marker plus separately mutable bounded cleanup outcome.
- `recording_history_decisions_v1`: revision-bound snapshot header and complete/pending state, maximum two retained projections per scope.
- `recording_history_decision_rows_v1`: bounded annotation/membership, merge-DAG and round rows, keyset paged with actual envelope byte limits; exact typed-reference indexes support transcript-page lookup without loading whole decisions.
- `recording_history_usage_v1`: per-recording/global retained and reserved logical charges; aggregate with old identity-store usage before either writer admits.

No existing identity table rebuild or automatic old-evidence migration. The schema marker, tables, indexes, triggers and erasure support are one all-or-none migration behind tested backup/restore and old-reader refusal. Source-specific destructive triggers distinguish append-only new facts from mutation/removal of bound facts. Proof/object rows remain retained until explicit erasure; retired observations remain competitors.

## Comparator ownership and passive reads

`MossJobs._reconcile_speaker_links` (`moss_handy_jobs.py:397`) remains the existing maintenance/discovery owner, but its one-second retry floor must not throttle actual comparison work. The smallest proposed owner change is one separate, globally tracked on-demand comparison task under `MossJobs` and its existing injectable thread factory/lifecycle. A positively acknowledged durable history append or an indexed durable dirty-scope discovery kicks it; no provisional capture or uncommitted notification is work authority; neither capture nor the app startup path waits for it. This task is separate from MOSS `_live` and the pending crop slot, so it cannot block its own dispatch or disappear when a text record is replaced. No new service, unbounded task queue or model supervisor is introduced.

The manager records the exact thread identity, task generation, recording/snapshot revision and one global CPU/memory reservation token before launch. The single task owns one resumable snapshot/cursor/cache. It loads bounded immutable pages in short read snapshots that are closed before compute, computes outside every DB/publication/admission/manager lock, and runs cooperative quanta back-to-back while its explicit CPU/RAM grant is valid. Initial checkpoint parameters to review are at most four indexed SQL operations under one zero-wait/250 ms/VM-step budget, pages of at most 32 rows/128 KiB, then at most 50 ms compute with ceilings of 4,096 dots or 32,768 primitive alias/crosspair-minimum/ranking updates. Check cancellation at least every 16 dots/64 updates. These are yield/checkpoint bounds, not a mandatory one-second sleep or a production duty default. No live PCM, CellLease, analyzer or model invocation is retained. Long scans, alias construction, every clustering round and projection are all resumable; no phase is hidden as one unbounded operation.

This is an explicit concurrency change. A comparison thread may coexist with primary/text processing only after one CPU lane within the approved existing CPU envelope and its entire incremental memory/temporary-buffer reservation are granted. The current native permit has process/RAM checks but no pure-comparison CPU reservation; a narrow comparison-resource token/accounting adapter must be added there and checked by other admissions, without masquerading as an inference owner or weakening automatic-turn rules. The benchmark's CPU3 assignment is not a production default. Python-thread/GIL contention, service memory accounting and primary delay need integrated measurement; if a thread cannot satisfy them, a separate process would be a new reviewed scope, not a silent fallback. With no grant, the task remains pending. Comparison memory, including an idle validated cache, is charged until positively released; resource pressure may discard only that recomputable cache, never retained evidence. Primary capacity cannot be held hostage to an optional cache.

`invalidate_session`, `close_admission` and `stop` cancel this same task, reject its stale publication and perform a bounded join. No replacement comparison task or reservation release is allowed while thread completion/ownership is unknown; `stop` remains false so the existing app cannot claim clean shutdown or release ownership early. One task can inspect persisted dirty-scope headers rather than accumulating an in-memory queue; a bounded scope rotation and total-work/deadline refusal must be fixed in the integration gate. Ordinary legacy reconciliation remains separate and unchanged.

Convergence needs explicit backpressure: while one full comparison snapshot is building, defer new identity observation reservations only with visible pending/skipped counters. Primary transcription and text storage continue. A reservation/invocation already admitted before the freeze is not thrown away; its exact eventual append can force a rebase using validated prefix scores. After those bounded outstanding operations settle, no further observation admissions enter until the build publishes or terminates with an explicit pending/refused result. Already-admitted competitors are never dropped, and accepted late alias/witness metadata or destructive authority invalidation takes effect immediately even if it invalidates the build. Reopening admission requires the same current revision-bound owner. This reduces actual sampling below a nominal cadence; it is not a hidden queue of historical PCM.

The rejected 50 ms/one-second arrangement would need at least 196 turns (3.3 minutes) for the measured 9.759-second warm pass and about 48.5 minutes for 145.6-second cold scoring, before overhead, and cannot support 60-second arrivals. The on-demand owner removes that artificial throttle but does not prove production convergence: the benchmark is one reduced all-abstaining pass, not worst-case merges or concurrent primary work. The earlier 96 MiB raw-array estimate is also not a grant; the 2,884-row prototype measured about 117.41 MiB combined owned RSS. Actual integrated CPU duty, incremental RAM, complete-history arrival/backpressure behavior and worst-case bounded work remain approval gates. New-history append and startup only mark/kick work pending; `_publish_probe_batch` and startup `speaker_links.reconcile` must never synchronously run a cold rebuild. Existing `app.py` wiring can remain unchanged only if that adapter behavior and existing `jobs.stop()` ownership check suffice; otherwise the narrow startup/shutdown edit joins the allowlist. Final publication still requires complete exact coverage and the current DB revision CAS.

Current settings do couple `recording_speaker_links_enabled` to `moss_automatic_enabled` and an absolute speaker-model path (`settings.py:177–187`); `TranscriptStore.__init__` currently uses that same flag. A retirement marker alone does not enable model-disabled HTTP reads. The smallest separate read route is the opt-in `recording_speaker_history_read_enabled`: `transcript_store.py` uses producer-enabled OR read-enabled to expose saved history, while settings preserve all producer constraints. The new read flag must not construct a probe/model manager, reserve permits, execute comparison/recovery writes or trigger inference. It uses the existing transcript endpoint and pure indexed history getters in the caller's DB snapshot. Fully matching retired-source certificates/markers can support saved revision-bound projection without files; active sources lacking restart revalidation are historical/pending with no fresh positive-current claim. Old-policy behavior and default-disabled exposure remain unchanged. Test a models-disabled/start-worker-false server reading known retired history and prove no producer or comparison work starts.

## End-to-end path and early evidence

A live qualified core reaches `Capture.prepare` while exact owned PCM exists. A bounded read checks immutable sampling policy/due state; selection uses the original 2-second crop/100 ms erosion and existing clean-attribution rules. Copy one 64,000-byte crop only if the single shared staging owner is free. Release all capture/analyzer/lease resources normally. A positive primary commit acknowledgement enables exact packet/ref binding and a post-ack idempotent scheduling claim. Unknown primary acknowledgement always discards the optional crop; a later packet lookup cannot reopen scheduling.

The pending owned copy survives normal cohort/model cleanup, then receives its alternating automatic turn. The Worker thread synchronously reserves the existing permit with `automatic_primary_probe`; the existing manager runs a fresh probe (10-second execution/5-second cleanup). Positive cleanup and fresh exact live authority are prerequisites for atomic certificate append. Exact storage-only acknowledgement resolution and existing unknown-child containment apply. The shared history then compares all admitted typed observations, aliases and hard witnesses, preserving prefix scores but publishing only a complete matching snapshot. Incomplete work remains pending.

An illustrative, unapproved policy bootstraps at most 6 naturally clean attempts in the first 120 source seconds with a 10-second source-start gap, then uses 60-second source-time buckets plus monotone next-due frames. Successive owned cores can naturally provide at least three source-disjoint groups; duplicates/overlap collapse or veto and cannot manufacture evidence. Nearby non-overlapping audio has unqualified statistical dependence. Three groups mean current/best/runner-up evidence, not three same-person votes. Sampling never uses reference labels, novelty or confidence feedback. Post-ack persisted claims survive restart; empty/busy buckets are skipped without historical replay or catch-up.

That example gives at most 724 primary opportunities in 12 hours and 2,884 in 48 hours before missing crops, busy slots, authority/execution failures or quota saturation. MOSS may add up to four certificates per admitted batch, including aliases that still occupy rows/bytes. These are opportunity/storage counts, not speaker counts or total-capacity promises. No 32- or 4,096-observation product lifetime ceiling is prescribed; actual RAM/work/disk bounds and saturation require review. The upstream durable primary-provenance ledger remains an independent limit: its existing 128 MiB recording budget exhausted after 5,801 dense synthetic opportunities, about 16.9 nominal hours, despite a sparse 48-hour retention result (`docs/RECORDING_PRIMARY_PROVENANCE.md:114`). This history's nominal 2,884 samples cannot guarantee 48-hour capture availability. Missing/over-capacity provenance causes an explicit upstream abstention, separate from new-history quota saturation; no provenance quota is changed here.

## Smallest model-free acceptance gate

One synthetic integrated fixture must exercise the actual owned-copy→positive primary commit→normal model/cohort cleanup→fair automatic turn→mocked fresh probe→positive cleanup→certificate append→complete current snapshot path across at least three naturally ordered source-disjoint cores, with simultaneous queued text work. The probe is mocked; no model or gold-labelled audio is needed.

Then targeted negatives cover: every primary/claim/reservation/append lost-ack point; optional exceptions preserving primary progress; one-slot bytes and alternating refusal fairness; bounded comparison quanta/cancellation, model-disabled passive reads with no work started; no lease reuse; duplicate/overlapping evidence unable to strengthen acceptance; source reset/cancel/deletion; current exact proof/vector/space mismatch; ordinary outside-bound append; missing proof; mixed old/new quotas; old-reader refusal/backup restore; stale snapshot CAS; exact-ref annotations whose duplicate matches cross page boundaries or disagree; incomplete annotation reads never produce a positive first-match result; legacy transcript behavior unchanged; reviewed compact-versus-legacy <=32 semantic fixtures. Retirement adds active-probe races, commit-before-unlink crash recovery, replacement-path refusal, unmarked absence, retained competitors and actual derived-data erasure. All DB/proof/byte maximum tests require their own explicit implementation/test approval, as does any new SQLite physical sizing benchmark.

After these gates, a separately authorized prospective actual test may qualify the fresh producer and resource behavior. External gold/RTTM stays outside production and is used only afterward for evaluation. This slice produces reversible recording-local annotations, not cross-day identity, enrollment or a qualified accuracy claim.
