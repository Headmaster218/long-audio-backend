# dev13 功能检查：范围与结果

版本：`0.2.0rc3.dev13`。开发源码检查点基于已发布 dev12 `76175dfce9475fe1d04799b6cf2d7aeea2045de7`，未创建 release/tag。运行时代码已固定，本报告分别记录源码检查、先前一次已有 30 秒音频的源码模型/API 运行，以及后续 wheel 构建、安装检查和另一次安装包的 30 秒模型/API 运行。

**当前状态：源码及安装包的两次有界功能检查均已完成，独立复核确认结果、存储一致性和进程退出。** 源码与控制参数绑定、结果一致性、隐私边界、载荷上限和进程清理已核对。安装检查使用全新包 target，但复用既有合资格依赖，不是全新依赖齐备虚拟环境验收。后续若修改运行时代码，须重新界定这些结果的适用范围。

## 1. 本版改变了什么

默认关闭的 FrameMN 旁路向既有候选账本加入未验证的时间候选，不替换 Zipformer、主事件、ASR 非语音门控或主转写；没有新增端点或数据库表。基础/inference 依赖不变。Torch 系列为事先配置的可选 CPU 运行时，权重只接受显式本地文件，不自动下载或随包分发。

唯一策略 `knock-001-median9-experimental-v1` 使用 447 类顺序中的 Knock（索引 228），九帧中值滤波后严格 `score > 0.01`。该阈值选于五标签并集的小规模实验，移用于 Knock 单类仍属描述性实验；本轮不是新的质量评测。

10 秒模型 tile 在最多 60.01 秒的 analyzer 输入内顺序执行；先连接有效分数，再做跨内部 tile 接缝的 median9，仅在实际 analyzer 两端反射。模型上下文仍分 tile 独立，外层 analyzer 之间不共享连续滤波状态。40 ms 是分数间隔，不是时间精度或延迟；本轮不证明任意重分块等价。

## 2. 源码与既有分数检查

- 选定源码回归：一次完整运行中 224 个测试、166 个 subtests 通过，覆盖默认关闭、参数与延迟加载、静音跳过、失败隔离、窗口/tile 清单、载荷边界、provenance 和事务提交计数等行为。
- 独立选定复跑：153 个测试通过。它与上一项有覆盖关系，不能相加为新的总测试数。
- 解码一致性：读取 48 个已有分数数组，分别比较 8 组独立的 60 秒序列，14 对合并后区间的整数样本支持完全一致。每组在自己的 analyzer 两端反射；没有把不同组拼成一个连续录音。

分数一致性检查没有读取 checkpoint、没有新增模型调用，也没有新增分数文件；它检验 decoder 的支持区间一致性，不是新的神经模型质量评测。合成分数、假模型和事务测试也不提供真实准确率结论。

## 3. 30 秒真实模型/源码 API 检查

使用已有兼容 CPU 运行时、本地 checkpoint 与已有音频，通过本版 Linux CPU 源码服务运行。这不是全新单环境安装配方或已安装 wheel 的验证。观察到：

- 主任务达到 `done`，已提交 core 进度为 0 → 12 → 27 → 30 秒。
- 三个 analyzer 支持范围为 [0,17)、[10,29)、[25,30) 秒；对应 FrameMN 模型调用为 2 + 2 + 1，共 5 次。
- 持久化 5 条 FrameMN 时间候选及 13 条原有候选，失败窗口为 0。候选数量按实际 tile 计，包含正区间为空的行。
- HTTP 候选查询、变化流与只读数据库中的 18 条候选精确一致，两条原有事件也一致；按已提交窗口累计的执行计数与实际调用相符。
- 观察到 2 条 owned positive row-runs，投影到时间轴为 [9.8,10)、[10,10.48) 秒，可在内部 10 秒模型接缝处连接；后一个 analyzer 的重复上下文拥有 0 个正样本。这是原始支持与 core 所有权裁剪的功能证据，不表示两个独立真实事件；出现正区间也不是本次接受条件。
- 本次检查记录耗时 26.261 秒，测试驱动返回 exit 0；服务按计划收到 SIGTERM，并经等待确认返回码为 -15。两者不是同一个进程的退出状态，不把服务终止写成 exit 0 或额外的优雅关闭保证。

本次候选 payload/provenance 最大值分别为 1,624/841 字节，低于既有限制；这是该次样本的实际观察。

原始 `temporal.frame_runs` 保留 tile 相对的半开帧区间；`owned_tile_sample_range` 与 `owned_sample_runs` 保存 tile 相对的半开样本支持。以 640 样本转换原始帧边界，并按实际 tile 长度裁剪；所属 core 的边界可落在网格内部，不代表模型变得更精确。现有 `/sessions/{session_id}/event-candidates` 即可读取，详见 [完整字段契约](FRAMEMN_EXPERIMENTAL_CANDIDATES.md)。

## 4. 后续 wheel、安装及真实 API 检查

构建来源为已发布提交 `1ee53f53d52cb26aca656aca37504b765fe0c822` 的精确 397 文件源码树（tree `38b5ddc74c9c43844d1b61e66a5176094994f116`）。使用标准宿主 pip/setuptools/wheel 离线构建，再使用合资格运行时的 pip 安装到全新 `--target`；基础依赖沿用该运行时，没有解析或安装依赖。这不是全新依赖齐备虚拟环境，也不把第 3 节的源码运行改记成安装包运行。

- wheel：`long_audio_backend-0.2.0rc3.dev13-py3-none-any.whl`，527,351 字节，SHA-256 为 `46cf47be7e2ad4eb361e4db4ab5d4f638499a4bf6585ef6ab0b67a3aa05745e2`。
- wheel 共 118 个成员，114 个包文件在发布源码、wheel 和安装 target 中逐字节一致。上游 `LICENSE` 与 `ADAPTATION.json` 均包含在包内；根级 MOSS manifest 不是 wheel 成员，按安装指南单独复制。
- 默认关闭检查完成安装包的 `Settings`、应用与普通 `AudioAnalyzer` 导入，并在 worker 关闭时构造含 55 条路由的应用。Torch 不可用且未导入，未导入可选 FrameMN 模块或读取模型；没有启动服务、构造 analyzer 或执行推理。本探针最初因自身保护器误拦 `find_spec` 检查而失败；仅修正测试探针后通过，原失败记录保留，产品代码未改动。
- 随后使用同一已安装包、事先准备的可选 CPU 运行时及本地 checkpoint，完成另一次 30 秒真实模型/API 检查：主任务 `done`，3 个 core 的进度为 0 → 12 → 27 → 30 秒，5 次 FrameMN 调用成功，失败窗口为 0。
- 持久化 5 条时间候选、13 条原有候选及 2 条原有事件；HTTP、变化流与清理后的不可变只读数据库结果精确一致。独立审计逐字段对照先前源码运行，除新运行的 chunk UUID 外，每个候选与事件字段均一致；各 core 的门控及 FrameMN metadata 也精确一致。该结论限于这两次固定输入的运行。
- 安装包检查耗时 25.468 秒，测试驱动经等待确认 exit 0。所属服务经等待确认返回码 -15，清理后无已知仍存活的子进程；服务终止不记作 exit 0，也不额外推导优雅关闭保证。

此处只补充文档记录，构建及测试辅助脚本、wheel 和模型权重不随这次文档更新发布。

## 5. 资源观察与失败语义

第 3 节先前源码运行的进程树 RSS 采样峰值为 1,606,688,768 字节，耗时 26.261 秒；第 4 节安装包真实运行的采样峰值为 1,608,830,976 字节，耗时 25.468 秒。两次均没有保留完整采样序列或最大采样间隔记录，因此不能证明连续真实峰值，也不能据此授予内存资格或推广到其他机器、并发与音频长度。这些耗时只描述各次运行，不是延迟或吞吐承诺。另一个无模型默认关闭探针的自身 RSS 峰值为 67,321,856 字节，范围仅限导入及应用构造，不能作为推理内存估计。

缺少可选依赖/权重、权重不符、输出无效或候选超限会拒绝本窗口全部可选输出，显式记录失败，保留主路径结果。原有主路径失败不会被改记成可选成功。静音为 `not_run_silence`，不加载 FrameMN、不进入推理，实际及预期调用都为零。关闭时沿用原 metadata；启用时使用独立命名空间，最后窗口状态与累计已提交窗口计数分别保存。
