# dev27：持久无结果诊断与说话人存储维护

## 版本与实际证据范围

本版基于 dev26，保持模型、默认关闭开关、依赖、持久 schema、执行及存储预算不变。没有新表、尝试账本或模型 worker。两项改动分别是无结果终态的有限诊断保留，以及已清理 probe 的存储维护可达性。

此前固定混合输入运行仍是退出码 1，不能改记为通过。该运行留下 30 个已提交结果及相应已验证 native 回执，另有 3 个无结果尝试未保留足够的原因与精确调用计数，所以总调用数仍未知。一个 probe 的待存储状态连续出现 389 次观测，首末相差约 877.7 秒。初次存储失败原因没有被保留；已确认的调度循环是待存储使模型就绪提示为假，进而没有维护机会。该观察不证明初始失败的具体 SQLite 原因。

本版尚未重跑真实模型。完整长时运行、文本时间戳质量、重叠内容恢复及说话人身份均未获得新的验收；队列或存储终态不能代替这些质量结论。

## 无结果终态

新任务沿用 job ID 与 original jobs epoch 作为单次、不可重放尝试的身份。在既有结果行的 metadata.outcome 内保存最多 1,024 字节的固定或白名单字段：控制器和管理器阶段、错误类别、原生回执计数依据、关闭与清理状态。允许有限 errno、返回码及关闭错误类型；不保存错误消息、路径、参数、PID、音频、转写或 stdout。

已经验证的 native 回执给出精确 construct/session/run 尝试计数。invocation_possible 为 false 时，只能证明当前边界尚无尝试；为 true 且没有已验证回执时，计数必须为 null/unknown，不能声称已经开始调用。子进程退出或成功清理不证明调用数。旧行、启动中断及非零子进程退出后未读取的回执均不补造证据。

原生与失败证据在取消或投影之前保留；清理、原始 handle 正向等待和 pin 释放观察稳定后，才封存精确终态元数据。手动及自动无结果任务把该元数据、终态、计费更新与相应自动状态变更放在同一现有事务中。提交确认丢失或存储失败时保留 owner、storage_pending 与封存字节，后续只允许同一元数据的存储重试或精确读回，不重新推理。已提交结果不可覆盖，旧中断记录不可补写新 outcome。

手动接纳及主任务抢占规则不变；手动无结果发布失败改为等待精确确认、fail-closed，不再尽力保存后直接退休。取消本身不能消除提交不确定性。既有明确删除与来源否决保持原边界，仅释放已确认清理的精确 owner。清理观察只覆盖已观测、归属明确的进程，不宣称扫描或证明未知进程。

## probe 存储维护

维护资格与模型就绪分开。只有精确的 live 记录及暂存 batch/attempt 存在，线程已结束、清理得到正向确认、lease 已释放，且没有未决 probe 清理或文本发布时，才可申请既有自动 turn。即使候选快照为空或到达 EOS，也有机会执行现有存储重试。

重试沿用同一 attempt、向量、预留和暂存负载；确认前不接纳下一个模型任务。既有一秒退避、所有权排除、数据库事务及时钟/VM 预算不变。一次失败维护机会只释放调度 gate，主任务可继续推进，暂存身份与计费保留。第一条脱敏存储失败类别保留为固定状态字段，不调用锁内日志 sink。

该路径不解决文本结果的未知提交，也不放宽 live thread、归属不明或清理未确认的拒绝。持续存储故障仍可能使最终 drain 失败；没有有限恢复时长保证。

## 模型无关资格

无结果诊断最终专项为 58 项通过；另一次相关回归为 217 项及 42 个子测试通过，明确排除两个 63/315 秒 core-yield 几何用例。首次专项的 47 通过、2 个 fixture 失败原样保留；修正 fixture 后另有 49 项通过，最终管理器分类补充后的 58 项单独记录，不把失败重写为成功。

probe 维护专项为 24 项通过；另一次相关回归为 238 项通过，同样明确排除上述两个几何用例。覆盖持续主请求、空候选/EOS、失败退避、精确 reserve/commit 确认丢失、取消/删除、确认后接纳及不确定清理拒绝。

调度与调用测试使用合成声学/原生提供者；另有全新 SQLite fixture 的真实竞争、存储及精确重试测试。未使用历史实际数据库或运行模型。各次运行采用 CPU 3、nice 19、300 秒、1 GiB RSS / 2 GiB AS 与 512 MiB fixture 上限；这里是限制，不是测量峰值。成功运行有正向原始等待，临时 fixture 已移除。离线安装验证单独记录，不把源代码资格当成安装包或真实模型资格。
