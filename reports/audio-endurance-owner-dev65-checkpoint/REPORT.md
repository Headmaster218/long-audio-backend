## One bounded recheck of the exact retained original

The new helper applies only to an already authenticated original process retained by its `Popen` handle. It allows at most **five observations within 100 milliseconds**. The deadline is further clamped to the remaining normal or cleanup budget and any earlier terminal-grace deadline. Retries do not grant a new deadline, and an exhausted or zero budget refuses.

Each live observation uses a fresh process wrapper, requires the pinned boot and stable kernel identity, and brackets metadata reads with kernel checks. The stable fields are PID, birth ticks, parent, UID, process group and session. Nonempty executable and argv values must exactly match the original binding. An empty executable must not hide a nonempty argv mismatch.

Empty metadata and exact-owner disappearance may be re-observed only inside the same bound. Nonempty mismatches, changed or foreign identities, permission errors and unresolved exhaustion remain refusals. A same-birth kernel zombie retains the existing zombie contract; observing it is not a new positive-wait claim.

An exit resolves only after the retained original handle reports a terminal code, a zero-time `wait` confirms that same code, and strict numeric-PID absence is established. The helper then raises a proof-bearing `Vanished`; it never returns a cached live row to disguise the exit. The namespace caller verifies the exact original handle, identity and attached proof object, then performs the independent original-exit check again. A bare disappearance exception, a proof from another handle, or PID reuse cannot bypass that gate.

## Fresh diagnostics, with sink failures kept distinct

Per-attempt context starts fresh and identifies the active stage, kernel observation, executable/argv field outcomes and exit-proof progress. Executable and argv diagnostics retain length and digest rather than raw private values. Records are bounded and use the existing evidence sink.

Namespace refusals now identify whether their context came from original-owner checking or namespace resource reads. The context is reset at the phase boundary, so an enumeration failure cannot borrow stale original-owner context, and an original-owner failure cannot borrow an unrelated old namespace observation.

Diagnostic failures fail closed. In particular, a diagnostic sink's `FileNotFoundError` is not treated as disappearing process metadata. A delayed diagnostic write cannot turn an exhausted recheck into a success, and a failed sink cannot grant resolved-exit authority.
