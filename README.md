## 0.2.0rc3.dev20：只读、暂定的统一转写

新增 `GET /sessions/{sid}/transcript` 和 `GET /sessions/{sid}/transcript/evidence/{source_ref}`，关闭模型及自动调度时也能读取现有证据。主响应 `reading` 是实际的统一显示结果：仅按已验证来源的采样坐标，选择完整覆盖所涉主 ASR 单元的相邻 MOSS 支持区间；保留未受影响的主文本，并在 `baseline_reading` 和完整链接的 alternatives 中保留原始主结果及未选中的模型候选。它是 `provisional_display_preference`，不保证内容完整、质量更好或 EOS 已知，也不会修剪单词、按字符串去重或推断跨任务人物身份。原主结果接口语义不变。

分页固定为 60 秒。每页最多 16 个相交 MOSS 结果、累计 2 MiB 结果负载、128 个完整主单元和 256 KiB 响应；**每个 session 最多 1,024 条自动绑定描述、累计 4 MiB 绑定**，每页都检查整个 session，不能靠分页绕过。16 条结果上限解决普通密集页的计数问题，不承诺任意长的自动 session 可投影。超限明确拒绝，不能当作空转写；没有更小窗口重试参数，必要时使用原主结果及结果历史接口。跨页支持仍是明确未解决候选，不强行拼接。旧 cursor 遇到相关证据变化返回 409。

主证据只提供当前精确哈希匹配的完整 ASR 字段，已改变返回 409、已缺失返回 404，不重放历史主文本。MOSS 证据使用不可变任务、结果哈希和原始索引，仍只代表历史快照。MOSS 说话人范围限定在任务和结果内，主 ASR 标签限定在 chunk、窗口和局部标签内，不是全局身份。

最终计数上限为 16 的源码通过 92 个模型无关专项用例。此前同一投影算法和存储实现、计数上限为 8 的版本通过 726 个既有回归用例及 46 个子测试；最终上限变更后未重跑该完整回归组。三组已保存结果的关闭模型 GET 检查通过，最终响应与此前版本逐字节一致。检查使用真实应用注册的路由和访问/响应生命周期逻辑，但没有进入应用 lifespan，不是服务启动验收；没有新增模型推理。固定的小样本比较显示去除了重复来源覆盖，但中文 17 秒样例的 cpCER 从 40.51% 退步到 87.34%。指标差距与任务局部说话人标签的碎片化相容，不能单独归因或宣称统一结果提高了识别与身份准确率。

## 0.2.0rc3.dev19：默认关闭的自动 MOSS 调度

新增显式 `--moss-automatic`，默认关闭。首个保证的输入范围是带已验证设备时间线映射、持久来源回执及精确保留 PCM 的时间戳 `recording_work`；合资格 overlap 证据写为持久意图，在普通 Worker 空闲时自动提交独立 MOSS 诊断，无需逐项 POST。须同时启用 `--moss-jobs --native-owned-support --native-owned-cells --native-owned-core-seams`，继承 CPU、Nemotron、`overlap_backend=none`、显式本地模型和普通 Worker 前置条件；拒绝与旧上传 seam 开关 `--native-owned-seam-cells` 组合，只包含普通 cell 和 core/reset seam。

主库的增量 schema 迁移包含两张表、八个索引和一个取消触发器，即使自动调度关闭也会应用；不回填旧 metadata，严格拒绝不兼容 schema，迁移后降级尚未验证。主文本、compact、该 core 的全部合资格意图和 next_offset 原子提交。意图的全局/session 行数、计费字节、非终态行及 proof 字节均有固定配额；容量不足时主路径停在未改变的 core offset，空闲调度可继续处理已有意图。缺失 PCM 或 cell 容量不足保持 pending，不推断成功；终态行不自动淘汰，最终仍可能需要显式删除所属 session 或调整部署条件。

## 0.2.0rc3.dev17：有界、持久的 MOSS 结构化历史

显式 MOSS 任务现在把最终验证及正向清理后封存的结构化 JSON 写入主 SQLite 历史账本。提交成功的结果不会随 900 秒任务 TTL、执行槽复用或服务重启自动过期；只有显式删除所属 session 才删除历史。历史列表、详情和结果在 MOSS 执行关闭时仍可读取。完整独立 raw 文本仍是易失状态；结构化结果中的诊断短语文本保持原样保存。

这些是历史诊断快照：保留原来源绑定、局部说话人标签、模型生成且未经验证的时间戳与观测到的模型/运行时出处，不恢复当前来源权限，不确认完整内容、全局人物身份或声学准确率。封存不证明来源在数据库提交瞬间仍有效。保存失败或确认不明时，一个不可变快照留在原槽位并阻止复用；显式 `retry-storage` 仅尝试一次相同字节的写入，不重新推理。未提交的内存快照不保证进程死亡后可恢复。

历史有有限的全局/session 行数与计费字节配额，没有 TTL、LRU 或自动覆盖。容量不足会明确拒绝新任务，已提交结果保持可读。可选写入仍需保守磁盘余量；它不是共享 WAL、物理占用或断电耐久的硬保证。

### 可选 overlap/MOSS 证据的独立容量边界

主音频可接收的时长不等于可选证据可完整保留的时长。可选 owner 仍有 4,096 个来源回执、1,024 个 cells 和 2,056 个 compact 提交上限。每个完整 10.5 秒工作 chunk 恰好对应一个新来源和 core 提交时，来源容量约为 11 小时 56 分 48 秒，未回收的 compact 容量约为 5 小时 59 分 48 秒；部分 core、cells 或字节预算可能更早耗尽。这些是容量换算，不是端到端时长承诺。

来源容量耗尽会在页面工作项中留下 `source_receipt_capacity` 与可选 gap；core 容量耗尽可从 `GET /chunks/{chunk_id}` 的 `metadata.native_core_seam.status` 读取 `core_receipt_row_capacity`。显式 compact 回收可帮助连续的安静已完成片段，但不能删除有引用的历史来腾空间，不扩大来源或 cell 限额，也不保证 48 小时可选证据。主任务完成不能解释为 overlap 完整恢复；本版不自动按年龄删除原文件、回执或 cells。

## 保留的 dev10 功能：可选 capture 与 cell 列表修正

这是开发分支，未创建 release/tag。它沿用 dev9 的有限 recording batch：客户端上传共享采样坐标已知的原始 PCM16 WAV，再明确 finish；只有重叠样本逐字节一致、坐标完整且并集连续，才生成去重后的工作片段。原始文件与来源映射保留，未知位置、不同 PCM 或空隙仍使批次 unresolved。

dev10 增加三项有界修正：

- 可选 capture 先组合已严格验证的整数帧坐标，避免已知帧网格的浮点加法造成额外拒绝；主路径原有浮点参数不变，真实非整帧、精度丢失和来源不符仍拒绝。
- 预期无重叠的 A–B seam 保留已验证的 B 尾部，供后续 B–C 检查；不会生成虚假的 seam cell，格式、来源和权威校验失败仍使状态失效。
- 单次 cell 列表操作复用一个 PrimaryAuthority 只读连接，每次读取仍新建并结束事务；无快照或值缓存，保留 2 秒、150,000 SQL VM 步数预算及最终权威校验。

## dev10 历史验证范围

dev10 产品源码的 205 个既有 authority/store/API 选定用例与 46 个可移植新增用例分两次运行通过；新增用例为帧坐标 12 个、静音 seam 18 个、列表连接 16 个。移植中先后发现两项过时或不适用的测试假设：仍按 0.5 秒等待既有 2 秒 owner 截止，以及比较微型 fixture 的回调计数步数。修正测试后得到上述覆盖并集；两次失败记录保留，不是一次连续 251-case 全通过。此前独立候选还有帧坐标 13 个、静音 seam 20 个和连接复用 16 个专项通过；它们与产品回归不能重复累计为一次测试。连接专项在复制的四-cell 数据上将默认列表的计数步数从旧实现的 150,100 步中断降至 15,000 步；一次主库连接中完成 134 个独立读取事务，原数据库未改动。这是复制数据与机制测试，不是 HTTP 或新环境资格验证。

真实 70 秒中文、21 秒 AMI 的前后对照中主结果等价，帧坐标拒绝均为 0，未复现待修正的实际帧失败。另一次 31.5 秒对照的主结果等价，但两侧都选中了 seam，未覆盖预期无重叠分支；其默认 cell 列表在上述连接修正前均遇到 SQL 预算拒绝。这些源码回归不能替代真实模型、安装环境或长期运行验收。构建、安装/import 与 API 检查的最新结果及具体范围见[开发分支说明](docs/DEV10_RELEASE_NOTES_ZH.md)。

## 使用边界

- 一个 capture 声明一个共享 PCM 采样坐标域，并独占一个全新空 `legacy` session。多个麦克风不能仅凭时间戳视为同一坐标域。
- 输入为单声道、16 kHz、16-bit little-endian PCM WAV。每批最多 16 个来源、32 个派生片段、300 秒唯一音频、32 MiB 录音复制预算；全局预算 128 MiB。更严格的服务配置和磁盘余量优先。
- 只支持全部输入齐备后的 finalized batch；不支持连续 sealed-prefix、任意/未知坐标对齐或近似 PCM 合并，也没有 12–48 小时全语音和设备录音可靠性结论。
- 普通 `/chunks` 仍拒绝时间区间重叠。MOSS 是显式、proof 绑定的独立诊断，不自动替换主转写，不保证文字准确率、重叠内容完整性或全局人物身份。
- native-owned cells、seam cells、core seams 和 MOSS jobs 默认关闭。显式开启仍须匹配已验证的 runtime、SQLite、VFS 与文件系统条件；相同依赖版本不等于可选能力具备资格，不能绕过检查。
- 主要为静音的 30 分钟主路径通过不代表全语音或可选链路可靠；此前计划 12 小时的运行在约 9 小时 20 分钟后丢失原运行句柄，结束和清理未获确认，不能记为 12 小时通过。

## 部署原则

固定依赖安装路径针对 Linux x86-64、CPython 3.12、CPU。Windows、GPU、其他设备与新环境长期运行未验证。无参数启动保留兼容默认；请使用安装指南中的显式 SenseVoice/Nemotron 参数。

一个数据目录只运行一个服务进程，不使用多 worker 或 reload。默认绑定 `127.0.0.1`；跨设备暴露前须自行配置访问控制和安全传输。`/health` 表示存活和能力状态，不证明模型内容正确。

升级前正常停服并完整备份。含 recording 数据的目录不能直接交给旧版本或仅改写 `chunks.path` 的旧迁移工具。模型和 native runtime 的独立许可证及第三方 notices 必须保留；下载、使用和分发前审阅安装指南中的上游条款。
