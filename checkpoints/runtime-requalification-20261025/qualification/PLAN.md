# New physical runtime qualification proposal — source only

Purpose: establish new finite physical evidence for the exact current interpreter, SQLite build and sqlite3 Python/bytecode closure. The previous dev48 package aggregate does not match. Original per-file inventory/harness is unavailable in the recovered shallow checkout. This gate does not restore old evidence or activate/change QUALIFIED_RUNTIMES. Root alone executes after independent source review.

## Scope and controls

Only a new private output directory, generated synthetic storage values and ordinary copies are mutated. No original A/short-control databases, audio, labels or models are opened. Source is hashed against a complete 943-file inventory. Product bytecode is rejected, rather than ignored; -B is not treated as proof that cached bytecode cannot execute. Input, harness and source fingerprints are rechecked at completion. Current stdlib Python/bytecode inventory and production runtime_fingerprints are measured under original 2-second owner budget; no acceptance profile is manufactured or installed.

The gate imports production CellStore._schema but never instantiates an owner or service. It applies the exact table/index schema and SQLite limits, with explicit unix VFS, DELETE journal, synchronous FULL, cache_spill OFF, cache_size -4096, temp_store MEMORY, mmap zero and finite SQL/attachment limits. Pragmas/limits are read back. Metadata values and cell bodies are deliberately synthetic and provide no native provenance or acoustic qualification.

## Four finite phases

1. Identity: includes parent source preflight, then a positively waited child that records exact interpreter, loaded SQLite identity, package inventory and source-module hash. No on-disk database is opened in this phase.
2. Fill: fresh isolated namespace; 128 bounded source rows then at most128 descending-size cell insertion attempts, each with a valid dependent foreign-key row. Actual SQLITE_FULL and page_count6144 are both required. Failure to reach the exact ceiling is INCONCLUSIVE. Original production schema, integrity/FK checks and a full typed six-table logical digest (including sqlite_master and sqlite_sequence) are retained. Close baseline before copying.
3. Controlled crash: at most TWO distinct bounded attempts sharing one120s phase. Each opens an ordinary copy, updates synthetic PCM inside a real SQLite transaction and enters actual COMMIT. Parent observes a valid positive-count journal header and at least one changed database page, sends SIGSTOP, obtains WSTOPPED|WNOWAIT acknowledgment, then SIGKILL and positive original Popen wait. No fabricated journal or injected SQLite/VFS fault is used. If commit completes before capture, preserve that miss and allow only the explicitly bounded second distinct attempt. A malformed captured journal fails the gate; it is not silently retried. Post-wait raw audit checks one header, nonce checksums, every original-page preimage, and nonzero changed database pages all covered by journal records.
4. Recovery: copy the interrupted pair into a separate isolated namespace. SQLite recovery must remove its journal, restore exact baseline database bytes and the complete typed oracle, and pass integrity_check/foreign_key_check. Original interrupted pair must remain hash-identical. Repeat source/runtime identity checks; retain all original waits.

## Limits and what they mean

- At most2 available CPU slots, nice+19.
- Four120-second phases including parent copy/audit work via SIGALRM; setup belongs to phase1. Normal worst case480s plus≤5s original-child cleanup and bounded receipt writes. Root still must positively wait the original top-level process. Infrastructure loss or uninterruptible kernel work cannot be certified clean by a timer.
- 1GiB per-process RLIMIT_AS, sampled parent+one-owned-child RSS≤256MiB. Sampling is not an instantaneous hard aggregateRSS guarantee. Parent journal-audit buffers are sampled while live.
- ≤192MiB charged output artifacts including allocated blocks/directories.2MiB is reserved during work for closing receipts; terminal-accounting.json records the terminal charge, with64KiB reserved for itself. Live namespace charge/slack are sampled and peaks retained; this is not a continuous allocation guarantee. Namespace uses only cells.sqlite3 and its journal; metadata/logs stay outside.
- Unchanged database24MiB (6144×4096), journal32MiB, allocated namespace envelope58MiB, slack2MiB, sector≤65536, one header. Output artifact monitor does not claim a platform-wide filesystem quota. Need at least256MiB free throughout.
- One child at a time; signal-blocked Popen ownership handoff; original Popen waits and process-group cleanup. No complete external process census claim. SIGTERM/SIGINT enter owned-child cleanup; SIGKILL/executor loss remains unknown until separately reconciled.

## Acceptance and non-acceptance

Root must first run the focused parser/guard controls once in its standard finite test environment, then inspect the independently reviewed frozen hashes before considering this one physical gate. Synthetic unit journals are NEVER physical evidence. This author executed neither tests nor SQL.

A zero process exit, PHYSICAL_GATE_COMPLETE_REVIEW_REQUIRED, positive waits, terminal-accounting, genuine interrupted pair and recovery receipts are jointly necessary, not sufficient for activation. Independent post-run audit must accept observations and their limits before any separate product profile change is proposed. No runtime hash replacement, budget increase, ignored pycache or repeated-until-pass run is authorized by this plan. A miss/failure preserves outputs and requires diagnosis, not blind replay.

The gate measures process-crash recovery, not power-loss behavior, independently verified fsync completion, universal quota enforcement, hostile same-UID mutation resistance, inference quality, production admission latency or the optional64MiB working reservation. Runtime/source identity can still fail later; operational admission tests remain a separate step after reviewed qualification.
