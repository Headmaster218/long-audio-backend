# dev30：被拒绝模型时间戳的有限数值诊断

版本：`0.2.0rc3.dev30`。本次改动只为已经被拒绝的模型时间戳增加有限证据，不修正模型输出，也不改变原有解析、接纳、丢弃和未定时文本保留规则。

## 结果字段

当既有 `invalid_model_timestamps` 分支实际拒绝一对时间戳时，结果可增加 `rejected_timestamps`：

- `support_duration_seconds`：当前支持音频的时长，单位为秒。
- `total`：进入该拒绝分支的时间戳对总数；不包括未匹配语法或先被说话人容量规则跳过的片段。
- `omitted`：没有保留数值对的数量，包括八对上限和结果字节上限导致的省略。
- `reason_counts`：每对只计入一个固定原因，优先顺序为 `nonfinite`、`negative_start`、`end_not_after_start`、`end_after_support`。因此同时存在起止反向和末端越界时，只计入前者；这不是跨片段的单调性检查。
- `pairs`：最多前八对，包含原始匹配顺序的 1-based `ordinal`、起止数值、固定原因及非有限数值类别。序号计入更早匹配但因说话人容量被跳过的片段。

非有限数值使用 JSON `null`，并以 `nan`、`positive_infinity` 或 `negative_infinity` 标识；有限值的类别为 `null`。既有语法不接受负数、NaN、Infinity 或指数形式文本，仍按原规则处理。过长的十进制数字可能在浮点转换后成为无穷值，其原始字符不会进入这个诊断字段。

诊断不包含原文、说话人标签、原始数值字符串、文件路径或其他负载。起止数值仍是相对于支持区间起点的模型时间，不添加录音原点，不夹紧越界值，也不删除或重排模型片段以制造合法时间戳。所有结果继续标记为 `model_generated_unverified`。

## 容量与兼容性

新增字段在原有结果大小判断之后附加，沿用 229,376 字节的投影上限，为控制器和清理信息保留原有余量。若空间不足，只减少新的数值对；若连计数和字段头都无法容纳，则省略整个新字段。不会为诊断删除既有文本或修改旧字段，旧的 oversize 处理仍先发生。

无实际时间戳拒绝、无效 UTF-8 或片段数提前超限时不增加该字段。因容量不足省略字段时，也不能把字段缺席解释为没有拒绝。旧的已保存结果继续原样可读，不补写、不迁移历史数据库。新字段使用现有结果行和历史接口保存，不增加任务、重试或模型调用。

## 验证范围

40 个模型无关专项用例通过，覆盖原因优先级、匹配序号、八对与 256 片段边界、非有限数值序列化、隐私字段、非零和大原点、旧字段逐字节一致、提前返回与大小拒绝、仅新字段裁减，以及全新 SQLite 中新旧结果的精确持久化和重新读取。

另一次相关回归通过 33 个用例及 10 个子测试，覆盖既有 adapter、禁用执行的历史 API、选定的存储字节边界和控制器投影路径；并非完整控制器或存储测试集。两个进程均正向等待结束，未观察到资源越界，临时 fixture 已清理。内存值是 pytest 进程的抽样值，不能表述为所有后代的聚合峰值。

这些用例不执行声学模型，不证明转写准确率、说话人身份或模型时间戳质量。此前 dev29 的 220 秒混合输入实际检查及其 8 个 schema-clean、3 个无效时间戳结果保留原资格；当时被拒绝的数值对没有保存，不能由本次新增诊断反推其精确数值或原因。新的诊断字段尚无真实模型运行证据。

安装采用既有固定依赖和标准离线 wheel 路径，默认可选能力、模型与运行环境要求不变；未增加依赖或改变数据库表结构。安装目标验证另行记录，不能替代真实模型或长时运行验收。历史实际结果见 [dev29 220 秒混合输入检查](DEV29_TARGETED_INTEGRATION.md)。
