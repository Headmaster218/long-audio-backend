# 严格模式运行时准备与资格边界

先按仓库根目录 `START_HERE_ZH.md` 恢复当前源码。普通 `pip install`
只安装 Python 包，不能使某个 Python、SQLite 或磁盘获得严格模式资格。
模型下载和 FTPS 接收进程也不能替代该资格。

## 在所选解释器和目标数据盘上先检查

用打算运行后端的**同一个解释器**，针对已存在、本人所有的 0700 私有数据目录运行：

```sh
python -B -m audio_backend.strict_runtime_preflight --data-dir /absolute/private/backend-data
```

命令不会创建数据目录或数据文件，不打开目标数据库，不获取实例锁，不加载模型，
不启动服务。它读取解释器和 SQLite 包指纹，并用内存 SQLite 检查版本、编译选项和
unix VFS。文件读取可能更新访问时间；这不是对抗同账号并发修改的安全边界。
报告只包含哈希、字段名和设备编号，不输出解释器或数据目录的私有路径。

- 退出 0 / `matched`：当前元数据通过产品内置的原始资格验证。只表示这一刻的
  运行时元数据匹配，不证明模型、锁、已有数据库、容量、服务或声学结果可用。
- 退出 2 / `unqualified`：没有匹配的产品资格，不能启动严格处理。
  `profiles[].mismatched_fields` 列出差异；不支持的 SQLite 绑定形式另有
  `fingerprint_error`。保持停止，不复制旧回执或修改常量来消除差异。
- 退出 1 / `refused`：目录/读取/验证条件不能安全满足。检查目录存在、权限和
  canonical 路径，然后使用相同配置重新检查。

该命令不是服务准入令牌。实际启动仍必须持有监督锁并重新运行原始验证；
检查后的环境或文件变化会使旧报告失效。

## 为什么新服务器可能拒绝

当前源码只内置一个精确运行时记录，包含解释器二进制及其真实路径哈希、
SQLite Python 包（包括已存在的 bytecode）、SQLite 源码/编译选项、绑定形式、
Linux unix VFS 和文件系统设备编号。普通发行版 Python 的动态 `_sqlite3`
扩展并未被当前记录支持。相同 Python 版本号或安装同一依赖锁文件都不足以匹配。

2026-11-04 针对当前云环境源码工作区所在数据盘的实际只读检查返回 `unqualified`，唯一差异是
`sqlite3_package_sha256`。同一机器的其他数据盘还可能出现设备编号差异。
这符合既有公开说明：成功的原生试验使用单独接受的
精确候选补丁，而新克隆的产品默认记录没有被改写。不能把该有限候选的成功
推断为任意新服务器可用，也不能把它复制成通用许可。

## 新目标的资格工作顺序

1. 固定实际目标解释器、SQLite 绑定/源码/编译选项、依赖与模型清单，以及数据盘。
   用上述命令记录真实差异。不要先把当前观测值写入产品 allowlist。
2. 在该目标数据盘的新建隔离测试目录中，验证原始 CellStore DDL 和全部原始资源
   约束下的容量、分配、回滚及进程崩溃恢复。测试必须有界并记录失败，不能改动
   实际数据。仓库 `qualification/cellstore_crash_probe.py` 是**已固定旧目标的历史
   实验**，不是通用新目标资格工具；它拒绝不同目标是正确行为。
3. 独立审查实际证据和实现差异，形成针对精确目标的显式源码资格更新及回归测试。
   仅生成指纹或 JSON 配置不构成资格，不能自动批准；不提供自动放宽或跳过开关。
4. 再从新克隆、在同一受审目标运行产品监督启动与短时真实原生管线，验证锁、模型、
   输入来源、关闭和导出。之后另做所需长时容量/性能测试。每步结论保持自己的范围。

当前仓库尚无完成第 2–4 步的任意服务器通用流程；目标服务器未测试前，交付状态
仍是“源码和可运行接收进程已备份，严格原生部署待目标资格”，不是一键生产成品。
没有自动迁移现有数据库、自动创建 session 或自动重试未知结果。
