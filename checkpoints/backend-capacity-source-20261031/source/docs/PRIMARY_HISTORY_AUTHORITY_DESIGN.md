# Additive durable admission contract

Design prerequisite, 2026-10-18. Scope: authority, proof retention and destructive-change handling. Compact-comparator and paged-annotation feasibility are separate work. This document does not authorize production implementation, migration or model execution. It does not adopt a 90-minute default, a 32-observation lifetime ceiling or a table rebuild.

## New certificate, created only by a successful live admission

A saved primary packet or old MOSS audit row is not a certificate. Only the manager's authenticated fresh invocation may request certificate append, after all of these conditions:

1. Primary commit and exact packet/ref binding were positively acknowledged. Unknown primary commit acknowledgement discards the optional crop; finding its packet later resolves audit/ownership closure only and never creates scheduling or inference permission. Unknown scheduling/reservation acknowledgement likewise grants no fresh inference permission: resolve the exact stored identity/outcome for closure only, with existing unknown-invocation containment when relevant. An intact owned crop is necessary for an already acknowledged in-memory transfer, but is not authority after an unknown acknowledgement. Never recover audio from a released lease or replay source.
2. The current source/packet/owner-generation checks succeed at reserve, dispatch and final append. Ordinary cohort/model cleanup is allowed: `_fence`, `_packet_current`, `_source_current` use current source/receipt/commit authority without requiring the released analyzer, native process, RollingWitness or CellLease.
3. Fresh `ProbeOperation` result is bound to this invocation and exact crop; vectors pass existing validation. Cleanup is positively complete before success append. Unknown invocation or cleanup produces no usable vector certificate and keeps existing containment/resolution behavior.
4. Under the existing publication guard and one bounded primary-DB transaction, recheck the exact proof, bound rows/mapping, current durable authority revision and byte quotas; append immutable certificate/vector/proof references, usage and history revision atomically. No separate success row can precede its proof. The private manager-to-store capability is not a public client-supplied cleanup boolean.

The certificate binds: typed origin (`primary_commit` or real `moss_result`), exact origin identity/digest, immutable packet/result/proof digests, all original source/primary references and crop coordinates, owned crop PCM digest, embedding-space/policy identity, exact original float32 vector bytes and digest, fresh invocation identity/positive cleanup outcome, and durable authority revision. A deterministic certificate key makes identical storage retries idempotent; conflicting bytes under that key refuse. A lost append acknowledgement triggers exact storage resolution only, never another model invocation. No grandfathering of prior audit packets or the exposed saved run.

Proposed physical representation separates a bounded canonical numeric/reference header (at most 2 KiB) from a 2,048-byte 512-component little-endian float32 BLOB. Preserve original components exactly, reject nonfinite/malformed vectors and do not renormalize. A digest binds both; the header limit is checked before allocation and is not permission to truncate proof. Exact DDL/byte charge includes indexes and identifiers and must be reviewed rather than reusing the old 4,096-byte batch-header allowance accidentally.

Successful certificates and vector-free attempt diagnostics are different records. A terminal failure does not require successful cleanup/embedding to remain diagnosable. Bounded sanitized reason enums plus counters preserve failure, capacity, pending and unknown outcomes; none supplies comparison evidence. Saturation stops admission, never erases a competitor. The earlier 4 KiB observation estimate is withdrawn: vector BLOB, header, copied receipts, dependency rows, proof and decision rows are separately charged.

## Proof-retention owner and lifetime

For primary observations, reference the exact immutable `recording_primary_packets_v1` row/body digest. It contains its commit. Its UPDATE trigger rejects mutation; its DELETE trigger permits only explicit session erasure; there is no core/recording FK (`recording_primary_provenance.py:255–289`). Thus ordinary compact-core GC does not require another live pin or duplicate primary packet. Retain the exact source Receipt bytes (at most 1 KiB each, `native_owned_cell_store.Receipt`) in a charged immutable proof object when recovery requires them; the certificate binds their digest. These are evidence bytes, not resident receipt-owner entries or execution authority.

For MOSS origins, a retained result alone does not necessarily contain every later crop/native proof. The new history must own a charged immutable copy/deduplicated object of the exact admitted typed batch proof wherever existing immutable retention is insufficient. Do not rely on a future old-scope batch existing. The current batch proof limit remains a per-object validation ceiling, not an allowance to allocate that maximum for every row. All copied proof bytes, source receipts and dependency indexes count against the proposed aggregate history budget. Old ledgers retain their own accounting. Missing referenced proof yields pending/invalid; no reconstruction or automatic re-certification.

Immutable dependency rows identify each bound source/mapping and exact primary ref, with indexes for destructive-change lookups. New source facts can be appended without invalidating earlier facts. These rows are retained with the certificate, not GC'd as performance hints. Their row/byte maxima must be included in the finite store contract; the comparator's 4,096-vector estimate does not budget an unbounded proof graph. Session erasure deletes new certificates/proofs/dependencies/decisions and adjusts usage in the existing primary deletion transaction before the old packet/chunk cascade.

## Durable revision and mutation writers

Use one recording-wide monotone signed-63-bit `authority_revision` plus a terminal `authority_blocked` reason. This is a conservative destructive-change fence, independent of append-only `history_revision` and the process-local owner epoch. Revision overflow rolls back. On a destructive change, atomically increment authority revision, set the blocked reason and invalidate the current decision pointer. Existing certificates remain auditable. The first contract provides no automatic scope reset, certificate re-certification, selective competitor removal or restart that unblocks it. A later recovery policy or genuinely new recording requires separate review.

Trigger/helper coverage must include:

- `storage.Store.set_state` cancellation and `lifecycle.cancel_descendants`: explicit cancellation affecting a bound source/recording. Ordinary pause, retry and successful forward `next_offset` movement do not rewrite past source facts.
- `recording_overlap.RecordingOverlap.cancel` / `abort_capture`: explicit recording cancellation/abort, including cases with completed prefixes retained. Existing text remains; this new identity scope is fenced conservatively.
- Bound `chunks` source identity, digest, owned path, duration/timeline or session-membership changes/deletes; bound `stream_chunks` mapping changes; bound `recording_work` mapping updates/deletes; bound recording origin/session changes; exact bound primary-row mutations/deletes. Triggers test OLD/NEW bound keys rather than invalidate on all INSERTs or every transcript revision. Duplicate new uploads remain aliases, not new independent votes.
- `native_owned_cell_store.Owner._receipt` / `_publish`: explicit observed source mismatch after commit (`source_changed_after_receipt_commit`, `source_changed_after_publication_commit`) calls the new durable invalidation helper before reporting known destructive invalidation. A generic exception or ordinary namespace supersession is unknown, not proof of source mutation.
- `lifecycle.delete_session`: advance/invalidate and erase in the same existing `BEGIN IMMEDIATE` transaction; keep the existing scrubbed session tombstone. Its post-commit `notify_deleted` hooks clean optional memory only and are not the durable writer.

Do not attach durable invalidation to generic `Owner.revoked()`: `close_admission()` also calls it. Ordinary model stop, owner shutdown, core `collect_compacts`, receipt-retirement cleanup, and owned crop/CellLease cleanup retire resources without mutating an admitted certificate. A captured pending crop still obeys its old live owner-generation fence and must fail on actual generation loss.

Routine append of a new source/upload/core outside the certificate's bound facts is stable. New observations advance history revision and cause comparison recertification, but do not invalidate existing certificates. Test this explicitly. A changed/remapped/deleted bound fact is destructive. Existing broad `transcript_revision` triggers are useful examples of atomic update plumbing, not the authority definition.

## Failed invalidation and restart: explicit remaining gate

All DB-origin destructive changes must perform invalidation in their own transaction or roll back. An in-memory fence cannot substitute if durable invalidation fails. For an observed filesystem mismatch, block current positive projection immediately; if the primary DB write is unavailable, report authority unknown and do not claim durable revocation.

A concrete conservative recovery option is to start new-policy positive projection closed after every process restart, then perform bounded source-receipt/signature and immutable-proof revalidation using certificate-owned receipt bytes and current primary mapping before marking the scope ready in memory. `PrimaryAuthority.receipt_valid` checks exact current chunk mapping and owned-path device/inode/size/mtime_ns/ctime_ns continuity, not a new full-content SHA recomputation or the live owner's retained receipt cache. This relies on the existing owned-file contract. Missing or changed source/proof remains pending or durably fences the scope. Ordinary owned-crop/receipt/core GC therefore remains harmless; deleting the original upload is not silently interpreted as harmless. This adds bounded recovery I/O and must be explicitly accepted and tested. If this recovery is rejected or originals are intentionally retired too, a durable pre-mutation/retirement protocol is required instead. No implementation-ready claim is made while that choice is unresolved. GET remains explicitly DB/revision-bound; it does not imply continuous live filesystem verification.

## Acceptance tests and later comparator boundary

Model-free certificate tests: cleanup-before-dispatch succeeds; append survives ordinary model/owned-PCM/receipt/core cleanup; exact reserve/commit lost acknowledgements never reinvoke; failed/unknown cleanup has diagnostic but no certificate; packet/vector/crop/space mismatch refuses; proof missing refuses; ordinary outside-bound source append preserves authority; bound mutation/cancel/abort invalidates atomically; deletion cascades new/old accounting; failure before/after invalidation commit and restart cannot restore a positive scope; no historical packet is promoted.

Compatibility remains additive tables plus the minimal known-schema refusal marker, with backup/restore and old-binary startup refusal tested before migration approval. No table rebuild. Existing old policy scopes remain byte-preserved and are not mixed with new-policy history.

Comparator work is separate: compact vectors/scores, complete all-history alias/witness coverage, resumable append-only score prefixes, exact <=32-node semantic equivalence, full-snapshot final revision CAS, bounded ranking/round work, and paged decision projections. Current Python pair sets/dicts/crosspair lists and 64 KiB decision JSON cannot simply have caps raised. At 4,096 nodes a cold triangular matrix has 8,386,560 pairs: 32,760 quanta of 256 dots, approximately 9.1 hours if served only once per second. That arithmetic is not a chosen scheduling rate or measured performance; the prototype must establish a viable work envelope without starving primary progress. No selected cadence, memory quota or actual identity quality is qualified by this contract.
