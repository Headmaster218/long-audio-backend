# 转写吞吐改进：源码检查点（2026-10-25）

本检查点在独立目录 source/ 中保存源码增量与测试，不覆盖仓库根目录代码；不是新的稳定发布，也不是可一键复现实验的基准包。基线为 [long-audio-backend 的已发布运行时检查点](https://github.com/Headmaster218/long-audio-backend/commit/8a3bb99a6949519e06fe8e2da274dc9acb70074f)。未修改的代码、依赖与运行说明继续以该基线为准。

## 主要变化

- 常驻分析器：由 Worker 独占复用子进程，最多成功处理 8 次请求后轮换；配置变化、中断、异常或提交未确认时退出复用。原进程退出未确认时禁止启动替代进程。
- 请求状态隔离：每次分析前重置 embedding 证据和 speaker-support producer，避免跳过阶段时沿用上一请求状态。
- 回执推进：每轮最多两步，仅已确认的持久化进展允许继续；保留冷却、停止检查和竞争保护。25 毫秒是协作式截止，不是硬实时上限。
- 关闭诊断：仅记录已有关闭判定与受限异常类别，不记录错误正文，不替代清理结果，不改变原来的成功判定。

## 已观察到的功能结果

一次真实公开 AMI A+B 音频试跑（AB06）：24 分钟输入，138 个分块、16 个来源、6 页全部完成；耗时 1335.366 秒；采样峰值 RSS 为 1,043,165,184 字节；服务与上传端均正常退出，退出码均为 0。

这仅是一次功能性表征，不是吞吐 SLA、严格内存上限或生产稳定性认证。RSS 是采样值，不能证明所有瞬时峰值均被捕获。

## 测试与夹具保留方式

- 产品目录保留回执推进、常驻分析器及回执恢复测试；改动后的恢复测试区分第二份回执已提交与未提交两种情况。
- 外部关闭诊断、关闭终态、历史 discovery 和 terminal-release 测试以独立、明确命名的归档测试保存，见清单。不会悄悄覆盖基线历史或 terminal-release 测试。
- 历史夹具修正驱动原有 discovery/comparison 延迟线程，保留同一记录转换、unknown-rival 拒绝与清理断言；终态夹具显式声明启动恢复已完成，并禁止意外恢复行为。修正夹具不等于修复产品缺陷，也不等于全套测试通过。
- 外部诊断测试仍引用原验证环境中的基线 app.py 路径；迁移执行前需显式提供对应基线或另行审阅路径适配。关闭终态测试依赖未纳入本包的实验 service_wrapper、test_service_wrapper。其余测试也依赖基线测试辅助模块。归档文件以 .py.txt 扩展名保存原始字节，避免默认测试收集；显式恢复文件名及所需依赖后方可执行，不承诺可直接运行。
