## Generate a target before execution

Replace every generated token consistently from current target information. Paths must be canonical and match their declared absolute or workspace-relative type. Generate numeric JSON values and Python integer literals for integer tokens. Generate 64-character lowercase SHA-256 values from exact current bytes. Generate file manifests only after all executable source substitutions are finished. Reject unknown or unresolved tokens.

The source, runtime, asset and control roots must agree across both directories and configuration. The diagnostic baseline, retained prior run/control roots and shared resource accounting are explicit dependencies. This checkpoint alone is not a complete runtime installation or launch recipe. Input audio, models, native libraries, Python packages, generated configs, inventory and validation records must be obtained or generated separately within the applicable permissions and licenses.

Git restoration recovers public source templates only. It does not recover private evidence or turn historical receipts into current target evidence. Never manufacture historical successful records, process identities, cleanup outcomes or prerequisite acceptance. Independently establish the required target prerequisites and preserve any prior failure status. If a valid derivation or execution prerequisite is unavailable, remain fail closed.

The final execution configuration separately pins exact complete configuration bytes and a fresh run. Presence of source, model bytes, old test labels or an executable Python file does not authorize or qualify inference. Linux /proc, pidfds, subreaper support and the configured isolated host interpreter are required.

## Technical contracts and limitations

Diagnostics retain original returns and primary exceptions, recording safe exception types and exact built-in SQLite codes/names only. Each process has at most 64 records. Lock contention, exhausted capacity and journal failures may lose observations. No diagnostic retry, SQLite setting, durability rule or inference operation count is changed.

The finite scenario preserves two 10.5-second uploads from a 21-second 16 kHz mono PCM16 source, exact upload/commit counts, a same-response natural seam crossing and one composite MOSS job. The public source retains the product and model provenance pins from its baseline; these do not supply missing target validation records.

The derivation checks require eleven source-row substitutions and 3,162 unchanged inventory rows, plus current descriptor checks explicitly distinguished from historical identity continuity. The fourteen-group suite is the passive delta qualification; the historical forty-two-group suite is not described as rerun.

The actual scenario uses CPUs 0 and 1, 4 GiB aggregate sampled owned RSS, 512 MiB of unknown-process reserves, 8 GiB address space, a shared 544 MiB old/new output budget and fixed 1,800-second outer endpoints. The retained unknown-process state remains unknown. Sampling is not a hard aggregate memory or disk quota. Original-handle cleanup and posthash are mandatory before success.

No acoustic accuracy, CER, independent per-upload revocation, in-flight cancellation, power-loss durability or forensic-erasure result is claimed. The watchdog is not a security sandbox.
