# Same-namespace coordinator: source checkpoint

This checkpoint contains an unexecuted portable coordinator template, its contract template and this status document. The private, environment-bound originals were exercised successfully through configuration, fixtures and independent review. Transforming those originals into these public templates does not transfer execution qualification.

## Why one coordinator is required

Configuration records the boot identity and PID namespace. Configure and every subsequent driver must inherit one PID namespace from the same supported invocation. Separate execution-tool calls can receive different PID namespaces, causing the unchanged driver's scope checks to refuse even when the workspace and boot appear unchanged.

The coordinator keeps configuration, the 24 guard cases, the 37 pacing cases, the child-free review pause and the eventual download in one serial process family. It checks each child's inherited namespace and retains each original process handle. It fixes the per-tool namespace mismatch by preserving the required scope; it does not remove or relax any namespace, boot, identity, source-pin, wait or cleanup predicate.

## Accepted evidence and snapshot status

The fixed private coordinator completed configuration and both fixture stages. The original guard and pacing driver handles were positively waited with exit 0. The accepted outer guards reported PASS, CONFIRMED cleanup, final source verification and no unresolved owned descendants. Raw results reported exactly 24 and 37 tests, with no failures, errors, skips, network requests or model work. The success and nonzero guard-fixture child waits were preserved. Independent review accepted the exact parked marker before the one-shot download approval was consumed.

At preparation of this source checkpoint, the fresh bounded download was running. It had no accepted terminal download and cleanup closure, and is not qualified complete here. Eventual acceptance still requires the retained original handle, final guard receipt, full 38-asset / 5,150,756,491-byte reconciliation, final source pins and confirmed cleanup. A running phase or individual file receipts are not terminal completion evidence.

The earlier interrupted acquisition remains historically unresolved after environment replacement. Recovering public source does not restore lost models, runtime, audio or database data, or establish the old process's completion and cleanup. Historical refusals remain refusals.

## Preparing a fresh private instance

These files are templates, not an admitted launch package. This particular coordinator binds preserved namespace-refusal history. Those private preservation files are not supplied or restored by Git. A future fresh environment must generate and independently review its own local binding configuration and prerequisites; substituting placeholders alone is not a drop-in executable recovery command. The templates deliberately contain unresolved REVIEWED_* values. Before any future execution, make private working copies and replace every reviewed workspace/layout path, host path, boot/device identity, independent-reviewer identity and preservation-file size/hash value with exact independently checked values for that instance. Numeric placeholder identifiers in coordinator.py must become reviewed integer literals; matching numeric placeholder strings in contract.json must become JSON integers. No placeholder is a fallback value or permission to skip a check.

Keep coordinator.py and contract.json as the only files in the fresh private coordinator directory before launch; this README belongs outside it. Prepare the independently verified prerequisite packet, product source, preservation records and proof source separately. The work path must be fresh and the runtime container absent. The published packet, asset and host-content pins are retained provenance constraints, not a claim that arbitrary replacements qualify. The pinned host bytes/version, CPU 3, nice 19 and resource limits remain explicit requirements. The sole reviewed launch must bind the exact final coordinator and contract hashes and use the required isolated host flags. Configuration and all drivers must then run as children of that same coordinator invocation.

The approval record must bind the exact current marker, reviewer, nonce, boot, namespace, configuration hash and review endpoint. It is consumed once while the review pause has no children. Never reuse an approval from another instance. The owner-controlled filesystem handoff is not cryptographic authentication of other same-UID writers.

## Retained bounds and exclusions

The fixed clock envelope, separate phase ceilings, 600-second review limit, 10,800-second download budget and 60-second coordinator overhead/cleanup allowance remain unchanged. Original child work and cleanup endpoints are retained; fallback signaling is bounded and pidfd-only. Every original handle requires a positive wait. Refusal, changed pins, stop requests, expiry or uncertain cleanup prevents a successful next phase or terminal claim.

The coordinator retains sampled RSS checks, inherited address-space limits, bounded output membership, exclusive receipt creation and finite loader observations. These are not continuous loader verification or a hard RSS-allocation guarantee. Download remains one attempt per artifact, without automatic retries, byte-range resume, extraction, installation or model work.

The public transformation was checked by exact inverse-byte reconstruction of both fixed originals and by a closed publication allowlist. Neither transformed template was executed, imported or tested. No active packet, acquisition evidence or older published snapshot was changed. Private configurations, preservation maps, operational identities and receipts, logs, audio and model payloads are excluded. There is no installation, runtime, storage or model qualification in this checkpoint.
