## Recovery and privacy

These are unexecuted, non-runnable recovery templates. Only literal tokens containing private local bindings were substituted: product/runtime/guard/spec/run paths, interpreter/profile/source pins, accepted fixture-receipt path, exact support duration/frame counts, support-dependent context/prompt/generation counts and CPU bindings. A private reverse map reconstructs byte-identical and AST-identical original source. All other source bytes, assertions, imports and control flow are preserved.

Recovery needs newly reviewed local bindings, complete source/input pinning, dependencies, resource admission, separate execution authority and fresh qualification. PROFILE, REQUEST, source freezes, actual authority, execution specs and raw outputs are deliberately absent. Do not weaken validation to bypass missing evidence. A permanent claim is not retry permission; a hard deadline exit cannot fabricate successful close or final posthash evidence.

Original frozen files and all execution evidence remain untouched. Private maps/reviews, settings, environment values, credentials, exact local run/session/lineage identifiers, manifests, receipts, logs, raw output, transcripts, audio, model and runtime data are excluded. Generic schemas, output basenames, environment variable names, standard system loader aliases and synthetic fixture literals remain code. No project imports, tests, model/audio reads, network activity, Git edits or publication occurred during backup preparation.
